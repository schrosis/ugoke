# ugoke run

```text
ugoke run [options] <workflow>
```

名前で指定したワークフローを実行し、終わるまで追いかけます。実行する前に、`ugoke validate` と同じように定義を確かめ、問題があれば実行しません。順に読む説明は、ガイドの「[ワークフローを実行する](../../guide/run.md)」にあります。

## 引数

| 引数         | 内容                                                       |
| ------------ | ---------------------------------------------------------- |
| `<workflow>` | ワークフローの名前です。たとえば `deploy`、`release/notes` |

## オプション

| オプション               | 内容                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `--address <address>`    | 使う Temporal Server のアドレスです                                                                                                             |
| `--input <json-or-file>` | [ワークフローの入力](../workflow-definition.md#ワークフローの入力)です。JSON のオブジェクトか、`.json` のファイルのパスです                     |
| `--detach`               | 実行を始めて、すぐに終了します。常駐プロセスが実行します。答え待ちは `ugoke inbox list` に出ます。`--address`、`--from-ai` とは一緒に使えません |
| `--from-ai`              | AI エージェントなどのプログラム向けに、JSON Lines で出力します                                                                                  |
| `-h`, `--help`           | ヘルプを表示します                                                                                                                              |

## 使う Temporal Server

次の順に決めます。

1. `--address` を指定したときは、そのサーバー
2. [プロジェクトの設定](../config.md)に `temporal.address` があるときは、そのサーバー
3. それ以外は、`ugoke daemon start` で起動した常駐プロセスのサーバー

常駐プロセスがステップを動かさないのは、次のときです。

- `--address` を指定した
- `temporal.address` があり、常駐プロセスがそのサーバーでステップを動かしていない。たとえば、常駐プロセスが動いていない
- 常駐プロセスの ugoke のバージョンが違う。そのことを表示します

このときは、コマンドが自分の中で Worker を動かします。コマンドが終わると、`ugoke attach` で戻るまで、ワークフローは進みません。

`--detach` を指定したときは、実行を始めずに、終了ステータス 1 で終わります。

## 出力

ステップごとに、ステップの ID、script ステップが実行するコマンド（`│ >` の行）、コマンドの出力や AI の進み具合（`│` の行）、結果（成功は `✓`、失敗は `✗`、取り消しは `■` の行）を表示します。最後の行は、ワークフローの名前と結果です。

ステップの結果の行は、次の形です。

| 結果     | 行                                           |
| -------- | -------------------------------------------- |
| 成功     | `✓ <ステップ>  <かかった時間>`               |
| 失敗     | `✗ <ステップ>  <理由> · <かかった時間>`      |
| 失敗して続けた | `✗ <ステップ>  <理由> · continued · <かかった時間>` |
| 取り消し | `■ <ステップ>  cancelled · <かかった時間>`   |

かかった時間は、1 分未満なら `4.1s`、1 時間未満なら `1m 02s`、それより長ければ `1h 05m` の形です。

| 結果                | 最後の行                                                                                                                                   | 出力先     |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------- |
| 完了                | `<workflow>: completed (<実行したステップ>, ...)`                                                                                          | 標準出力   |
| 失敗                | `<workflow>: failed: <理由>`                                                                                                               | 標準エラー |
| 切り離した          | `<workflow>: detached. Run "ugoke attach" to continue`                                                                                     | 標準エラー |
| 取り消した          | `<workflow>: cancelled`                                                                                                                    | 標準エラー |
| `--detach` で始めた | `<workflow>: started <workflow-id> in ugoke daemon. Its questions wait in "ugoke inbox list", and "ugoke attach <workflow-id>" follows it` | 標準出力   |

定義に問題があるときは、`ugoke validate` と同じ形で、標準エラーに表示します。

切り離したときの `ugoke attach` には、`ugoke run` に指定した `--address` が付きます。常駐プロセスや `.ugoke/config.yaml` の `temporal.address` のサーバーでは付きません。

```text
wait: detached. Run "ugoke attach --address localhost:7233" to continue
```

## 終了ステータス

- `0`
  - ワークフローが完了した
  - `--detach` で、実行を始めた
- `1`
  - ワークフローが失敗した
  - 定義に問題があった
  - `--input` が正しくない
  - [プロジェクトの設定](../config.md)に問題がある
  - [プラグイン](../plugins.md)を読み込めない
  - サーバーの準備に失敗した。たとえば、常駐プロセスが動いていない
  - `--detach` を指定したが、常駐プロセスがステップを動かさない
  - 暗号化の鍵が壊れている
- `3`: ワークフローから切り離した。ワークフローは続いている
- `130`
  - ワークフローが `ugoke cancel` で取り消された
  - 実行を始める前に Ctrl+C を押した
  - 2 度目の Ctrl+C ですぐに終了した

## Ctrl+C

| ステップを実行しているところ                           | 1 度目の Ctrl+C                              | 2 度目の Ctrl+C                                    |
| ------------------------------------------------------ | -------------------------------------------- | -------------------------------------------------- |
| 常駐プロセス                                           | すぐに切り離す。ワークフローは続く           | —                                                  |
| `ugoke run` 自身                                       | 実行中のステップが終わるのを待って切り離す   | すぐに終了する。実行中のステップは失敗し、続けられない |

## ワークフローの ID

実行ごとに、`<ワークフロー名>-<UUID>` の形の ID を付けます。たとえば `ok-f61e5552-4fe3-4ab0-bba7-d70d37aaafbc` です。
