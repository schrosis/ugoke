# ugoke attach

```text
ugoke attach [options] [workflow-id]
```

プロジェクトの実行に戻り、終わるまで追いかけます。`ugoke run` から切り離した実行などに使います。順に読む説明は、ガイドの「[ワークフローを実行する](../../guide/run.md)」にあります。

## 引数

| 引数            | 内容                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------- |
| `[workflow-id]` | 実行の ID です。書かなければ、プロジェクトの実行を一覧にして、ターミナルで選んでもらいます |

## オプション

| オプション              | 内容                                                                              |
| ----------------------- | --------------------------------------------------------------------------------- |
| `--address <address>`   | 使う Temporal Server のアドレスです                                               |
| `--force`               | 別のバージョンの ugoke が始めた実行に戻ります。失敗することがあります                      |
| `-h`, `--help`          | ヘルプを表示します                                                                |

使う Temporal Server の決め方は、[`ugoke run`](run.md#使う-temporal-server) と同じです。

## 動き

- 選べるのは、このプロジェクトから始めた、まだ終わっていない実行です
- 1 つの実行を追いかけられるのは、1 つのプロセスだけです。ほかのプロセスが追いかけている実行には戻れません
- 実行のステップを動かしているプロセスがなければ、`ugoke attach` がステップを実行して、実行を続けます
- 戻ると、実行の始めからの進捗を表示します
- 実行は、始めたときの定義のまま続きます。あとで定義のファイルを変えても、動いている実行には効きません
- 表示、待機ステップの答え方、Ctrl+C の動きは、`ugoke run` と同じです
- 別のバージョンの ugoke が始めた実行と、バージョンを記録していない実行には、そのままでは戻れません。一覧では `(started by another version of ugoke)` と添えます。`--force` で試せますが、失敗することがあります

## 終了ステータス

- `0`
  - ワークフローが完了した
  - 戻れる実行がなかった
- `1`
  - ワークフローが失敗した
  - 実行を選ばなかった
  - 指定した実行がない
  - ほかのプロセスが追いかけている
  - 別のバージョンの ugoke が始めた実行に、`--force` なしで戻ろうとした
  - [プロジェクトの設定](../config.md)に問題がある
  - [プラグイン](../plugins.md)を読み込めない
  - サーバーの準備に失敗した。たとえば、常駐プロセスが動いていない
  - 暗号化の鍵が壊れている
- `3`: ワークフローから切り離した。ワークフローは続いている
- `130`
  - ワークフローが `ugoke cancel` で取り消された
  - Ctrl+C で終了した
