# ugoke inbox

```text
ugoke inbox list [options]
ugoke inbox answer [options] <workflow-id>
```

プロジェクトの実行で、誰かの答えを待っている wait ステップを一覧にして、答えます。`ugoke run` を切り離したあとの実行に、あとから答えるときに使います。

使う Temporal Server の決め方は、[`ugoke run`](run.md#使う-temporal-server) と同じです。

## ugoke inbox list

答えを待っている wait ステップを一覧にします。

| オプション            | 内容                                                                                 |
| --------------------- | ------------------------------------------------------------------------------------ |
| `--from-ai`           | プログラム向けに、JSON Lines で出力します（「[プログラムから使う](../from-ai.md)」） |
| `--address <address>` | 使う Temporal Server のアドレスです                                                  |
| `-h`, `--help`        | ヘルプを表示します                                                                   |

- このプロジェクトから始めた、まだ終わっていない実行の、待っているステップを出します
- ステップごとに、次のことを出します
  - 実行の ID と、ワークフローの名前
  - ステップと、何回目か
  - 始まってからの時間と、ワークフローの入力
  - `message` と、答えの宣言
  - 答えるコマンド
- 答えるコマンドは、常駐プロセスが動かしている実行なら `ugoke inbox answer` です。ほかの実行なら `ugoke attach` です
- `--address` を指定したときは、どの実行も常駐プロセスが動かしていないとして扱います。答えるコマンドには `ugoke attach` を出します
- Worker が答える待ち方のステップは出しません
- ステップを動かす Worker のいない実行は、何を待っているかを読めません。そのことと、`ugoke attach` で戻るコマンドを出します
- 読めない実行が 1 つでもあれば、ほかの一覧を出せても、1 で終わります

## ugoke inbox answer

wait ステップに答えます。

| 引数            | 内容           |
| --------------- | -------------- |
| `<workflow-id>` | 実行の ID です |

| オプション                | 必須   | 内容                                                                                                                                     |
| ------------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `--step <step>`           | はい   | 答えるステップの ID です                                                                                                                 |
| `--values <json-or-file>` | はい   | 答えです。JSON のオブジェクトか、`.json` のファイルのパスです                                                                            |
| `--detach`                | いいえ | 答えたら終わります。実行は常駐プロセスで続きます                                                                                         |
| `--from-ai`               | いいえ | 答えたあと、次の質問か終わりまで実行を追いかけます。プログラム向けに、JSON Lines で出力します（「[プログラムから使う](../from-ai.md)」） |
| `--visit <number>`        | いいえ | ステップの何回目に答えるかです。0 から数えます。`ugoke inbox list` が出す値です。省くと、いま待っている回に答えます                      |
| `--address <address>`     | いいえ | 使う Temporal Server のアドレスです                                                                                                      |
| `-h`, `--help`            | いいえ | ヘルプを表示します                                                                                                                       |

- `--detach` か `--from-ai` のどちらか 1 つを指定します
- `--detach` で答えられるのは、常駐プロセスが動かしている実行だけです。ほかの実行には、`ugoke attach` で戻るか、`--from-ai` で答えます
- `--address` を指定したときは、常駐プロセスが動かしている実行としては扱いません。そのため、`--detach` では答えられません
- `--from-ai` は、常駐プロセスが動かしていない実行には、コマンドの中で Worker を動かして答えます
- `--from-ai` は、ほかのプロセスが追いかけている実行には答えません
- 答えが宣言に合わないときは、受け付けません。ステップはそのまま待ちます
- ステップがもう待っていないとき、`--visit` の回でないときも、受け付けません
- `ugoke run` や `ugoke attach` がターミナルで聞いているあいだに答えると、そちらは聞くのをやめて、次に進みます

## 終了ステータス

- `ugoke inbox list`
  - `0`: 一覧を出した。待っているステップがなかった
  - `1`
    - 何を待っているかを読めない実行がある
    - プロジェクトが見つからなかった
    - [プロジェクトの設定](../config.md)に問題がある
    - サーバーの準備に失敗した。たとえば、常駐プロセスが動いていない
    - 暗号化の鍵が壊れている
- `ugoke inbox answer`
  - `0`
    - `--detach` で、答えた
    - `--from-ai` で、答えたあと、実行が完了した
  - `1`
    - 実行が答えを受け付けなかった
    - 指定した実行がない
    - `--detach` で、常駐プロセスがその実行を動かしていない
    - `--from-ai` で、ほかのプロセスがその実行を追いかけている
    - `--from-ai` で、答えたあと、実行が失敗した
    - `--values` が正しくない
    - プロジェクトが見つからなかった
    - [プロジェクトの設定](../config.md)に問題がある
    - サーバーの準備に失敗した。たとえば、常駐プロセスが動いていない
    - 暗号化の鍵が壊れている
  - `3`: `--from-ai` で、答えたあと、次の質問が来たか、実行から切り離れた
  - `130`
    - `--from-ai` で、答えたあと、実行が取り消された
    - `--from-ai` で、答えたあと、2 度目の Ctrl+C ですぐに終了した
