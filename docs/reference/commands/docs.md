# ugoke docs

```text
ugoke docs [options] [workflow]
```

ワークフローのつながりを図にした Markdown の文書を、定義のファイルの隣に作ります。図は Mermaid で書きます。

## 引数

| 引数         | 内容                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| `[workflow]` | ワークフローの名前です。たとえば `deploy`、`release/notes`。書かなければ、全部のワークフローの文書を作ります |

## オプション

| オプション     | 内容               |
| -------------- | ------------------ |
| `-h`, `--help` | ヘルプを表示します |

## 動き

- 文書は、定義と同じ名前で、拡張子を `.md` にしたファイルです。たとえば `.ugoke/workflows/deploy.yaml` なら `.ugoke/workflows/deploy.md` です
- すでにある文書は、作り直します。ただし、`ugoke docs` が作ったのではないファイルは、書き換えません
- `ugoke docs` が作った文書を手で直しても、次に作り直すと、直したところは消えます
- 定義に問題があるワークフローは、`ugoke validate` と同じようにエラーを表示し、文書を作りません
- 全部のワークフローを作るときは、1 つが失敗しても、ほかのワークフローを続けます。ワークフローの名前にできないファイルは、そのことを表示して飛ばします

## 終了ステータス

- `0`
  - 文書を作った
  - 作るワークフローがなかった
- `1`
  - 作れなかった文書がある
  - プロジェクトが見つからなかった
  - [プロジェクトの設定](../config.md)に問題がある
  - [プラグイン](../plugins.md)を読み込めない
