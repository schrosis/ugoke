# プラグイン

プラグインは、ai ステップのプロバイダーや、wait ステップの待ち方を足すパッケージです。ugoke に組み込んであるのは、待ち方の `terminal` だけです。

## 使う

パッケージをプロジェクトに置き、[プロジェクトの設定](config.md)の `plugins` に、パッケージの名前を書きます。

```yaml
plugins:
  "@ugoke/adapter-ai-claude-code":
```

- パッケージは、プロジェクトのルートからたどって探します。見つからなければ、ugoke の隣から探します
- 書いた順に読み込みます
- プラグインは、ugoke と同じプロセスで動きます。ワークフローのスクリプトと同じように、信頼できるものだけを書いてください

## 名前

定義には、プラグインが足したプロバイダーや待ち方の名前を書きます。

- `@ugoke/` で始まるパッケージのものは、そのままの名前です。たとえば `claude-code` です
- ほかのパッケージのものは、`<プラグインの名前>/<名前>` です。たとえば `acme/echo` です。プラグインの名前は、パッケージの名前ではなく、プラグインが決めた名前です
- 同じ名前のプラグインや、同じ名前のプロバイダーや待ち方が 2 つあると、エラーになります

## 設定

`plugins` の、パッケージの名前の下に、プラグインの設定を書きます。

```yaml
plugins:
  acme-echo:
    greeting: hi
```

- 設定は、プラグインの決まりで確かめます。プラグインは、確かめた設定を受け取ります
- 何も書かないと、空の設定として確かめます。プラグインが必須の設定を決めていれば、エラーになります
- 設定を受け取らないプラグインには、何も書かないか、`{}` だけを書きます
- 設定の値は、実行の記録に残りません

## 問題があるとき

次のときは、`ugoke validate`、`ugoke run`、`ugoke docs` は、何も実行せずに 1 で終わります。`ugoke attach` も、実行を追いかける前に 1 で終わります。

- パッケージが見つからない
- パッケージを読み込めない
- パッケージの既定のエクスポートが、プラグインでない
- 名前がほかのプラグインと重なる
- プラグインの名前や、足すものの名前が、決まりに合わない
- 設定が、プラグインの決まりに合わない

定義に書いたプロバイダーや待ち方を、どのプラグインも足していないときは、定義のエラーです。ugoke のプラグインが足すものなら、入れるパッケージを表示します。
