# ワークフローの定義

ワークフローの定義のファイルの項目と決まりです。書き方を順に知るには、ガイドの「[ワークフローの定義](../guide/workflow-definition.md)」を読んでください。

## 最上位の項目

| 項目      | 必須   | 内容                                                                                                                                                                              |
| --------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `$schema` | いいえ | エディターが使う JSON Schema のパスです。ugoke の動きは変えません。[ugoke schema](commands/schema.md)を見てください                                                               |
| `version` | はい   | 定義の形式のバージョンです。`v0.1` だけを受け付けます                                                                                                                             |
| `start`   | はい   | 最初に実行するステップの ID です                                                                                                                                                  |
| `steps`   | はい   | ステップの一覧です。キーがステップの ID、値がステップです                                                                                                                         |
| `inputs`  | いいえ | ワークフローの入力の宣言です。[ワークフローの入力](#ワークフローの入力)を見てください                                                                                             |
| `env`     | いいえ | すべての script ステップと ai ステップの環境変数です。名前と値の組で書きます。数と真偽値は、書いたとおりの文字列になります。値の[式](#式)は、`workflow.inputs` だけを参照できます |
| `dotenv`  | いいえ | script ステップと ai ステップが読む [dotenv のファイル](#dotenv-のファイル)です。プロジェクトのルートからの相対パスで書き、ルートの外は指せません                                 |

## ステップの ID

- 英字で始め、英字、数字、`_` だけで書きます
- `start` と `end` は予約語のため、使えません

## ワークフローの入力

`inputs` には、ワークフローが始まるときに受け取る値を、名前と宣言の組で書きます。名前は英字で始め、英字、数字、`_` だけで書きます。値は、`ugoke run` の `--input` で渡します。

| 項目          | 必須            | 内容                                                                         |
| ------------- | --------------- | ---------------------------------------------------------------------------- |
| `type`        | はい            | `string`、`number`、`boolean`、`choice` のどれかです                         |
| `options`     | `choice` のとき | 選べる値の一覧です。1 つ以上書きます。空の文字列と、同じ値を重ねて書けません |
| `required`    | いいえ          | 値を必ず渡すかどうかです。既定は `false` です                                |
| `default`     | いいえ          | 値を渡さなかったときの値です。`type` に合う値を書きます                      |
| `description` | いいえ          | 入力の説明です                                                               |

- `required: true` と `default` は、一緒に書けません
- 必須でない値を渡さなかったときは、`default` を使います。`default` もなければ `null` です
- 宣言にない名前の値、型の合わない値、`options` にない値を渡すと、実行せずに失敗します
- `number` の値は、`1.5` のように書きます。`1e3` のような指数の書き方は使えません
- 入力の値は、JSON で 512 KiB までです

## script ステップ

| 項目              | 必須   | 内容                                                                                                                            |
| ----------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `type`            | はい   | `script` です                                                                                                                   |
| `run`             | はい   | 実行するコマンドです                                                                                                            |
| `next`            | はい   | 次に実行するステップの ID か、`end` か、[分岐](#分岐)の一覧です                                                                 |
| `maxVisits`       | いいえ | 1 つの実行で、このステップが動ける回数です。正の整数で書きます。書かなければ、上限はありません。[ループ](#ループ)を見てください |
| `timeout`         | いいえ | ステップの最大の実行時間です。既定は `30m` です                                                                                 |
| `inputs`          | いいえ | ステップが受け取る値です。名前と[式](#式)の組で書きます                                                                         |
| `outputs`         | いいえ | ステップが出す値です。名前と[式](#式)の組で書きます                                                                             |
| `env`             | いいえ | このステップの環境変数です。名前と値の組で書きます。数と真偽値は、書いたとおりの文字列になります。値には[式](#式)を書けます     |
| `continueOnError` | いいえ | `true` なら、ステップが失敗しても、ワークフローを続けます。[失敗しても続ける](#失敗しても続ける)を見てください                  |

`timeout` は、正の整数に単位 `s`（秒）、`m`（分）、`h`（時間）を付けて書きます。たとえば `30s`、`5m`、`1h` です。

### 実行

- 作業ディレクトリは、プロジェクトのルートです
- 環境変数は、ステップを実行するプロセスのものを引き継ぎます。常駐プロセスで実行するときは、常駐プロセスを起動したときのものです
- `dotenv` のファイルは、スクリプトを実行するたびに読みます。読めないときは、ステップは失敗します。その値は、実行の記録に残りません。`env` の値は、実行の記録に残ります
- 同じ名前の環境変数は、`dotenv` のファイル、引き継いだ環境変数、ワークフローの `env`、ステップの `env` の順に、あとのものが使われます
- 環境変数の名前は、英字か `_` で始め、英字、数字、`_` だけで書きます。値は、文字列、数、真偽値で書き、数や真偽値は文字列にします。YAML が違う値として読む書き方は、引用符で囲みます（「[YAML の書き方の制限](#yaml-の書き方の制限)」）
- 途中のコマンドが失敗すると、スクリプトが止まります。パイプラインの途中のコマンドと、`if`、`&&`、`||` の条件として書いたコマンドは除きます
- 0 以外の終了ステータスで終わるか、`timeout` を過ぎると、ステップは失敗します
- ステップが失敗すると、ワークフローはそれ以降のステップを実行せずに失敗します。`continueOnError` を書いたステップは除きます
- 失敗したステップは、やり直しません
- `timeout` を過ぎると、スクリプトと、スクリプトが起動したプロセスに終了を求め、5 秒たっても残っていれば強制的に止めます

### dotenv のファイル

`dotenv` のファイルは、1 行に 1 つ、次のどれかを書きます。

- 空の行
- `#` で始まるコメント
- `名前=値`。前に `export` を付けても同じです

```text
# Settings for the staging server
API_URL=https://staging.example.com  # a comment after a space
export STAGE=staging
GREETING='Hello, $USER'
NOTES="first line
second line"
```

- 名前は、`env` と同じように、英字か `_` で始め、英字、数字、`_` だけで書きます
- 同じ名前を 2 度は書けません
- 値は、次の 3 つのどれかで書きます
  - 引用符なし：前後の空白を取り除きます。空白のあとの `#` から行の終わりまでは、コメントです
  - `'` で囲む：書いたとおりの値です
  - `"` で囲む：`\n` は改行になります。ほかの `\` は書けません
- 引用符は、値の先頭にあるときだけ、値を囲むものとして読みます。`A=a "b"` の値は、引用符ごと `a "b"` です
- 引用符で囲んだ値は、何行にもまたげます。閉じた引用符のあとには、空白とコメントだけを書けます
- `#` を含む値は、引用符で囲みます
- `` ` `` で囲んだ値は書けません
- `$USER` のような変数は、展開しません
- 1 行でも決まりに合わないと、ファイルのどの値も渡さず、ステップは失敗します

## wait ステップ

答えを待つステップです。答えるのは、待ち方によって、人か Worker です。たとえば `terminal` は人に聞き、[`github_pr`](wait-methods/github-pr.md) は pull request の出来事を Worker が確かめます。

| 項目      | 必須   | 内容                                                                    |
| --------- | ------ | ----------------------------------------------------------------------- |
| `type`    | はい   | `wait` です                                                             |
| `method`  | はい   | 待ち方です。`terminal` か、[プラグイン](plugins.md)が足す待ち方を書きます |
| `with`    | 待ち方による | 待ち方のオプションです。文字列には[式](#式)を書けます             |
| `next`    | はい   | 次に実行するステップの ID か、`end` か、[分岐](#分岐)の一覧です                                |
| `maxVisits` | いいえ | 1 つの実行で、このステップが動ける回数です。正の整数で書きます。書かなければ、上限はありません。[ループ](#ループ)を見てください |
| `inputs`  | いいえ | ステップが受け取る値です。名前と[式](#式)の組で書きます                 |
| `outputs` | いいえ | ステップが出す値です。答えを `result.<名前>` で参照できます             |

- 答えが来るまで待ちます。待つ時間の上限はありません
- 答えは、待ち方が宣言した値です。宣言に合わない答えは受け付けず、もう一度聞きます
- 必須でない値を答えなかったときは、`default` を使います。`default` もなければ `null` です

### terminal

`ugoke run` のターミナルで聞きます。

| 項目      | 必須   | 内容                                                                                                               |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------ |
| `message` | はい   | 聞く前に表示する文です                                                                                             |
| `schema`  | いいえ | 聞く値の宣言です。書き方は[ワークフローの入力](#ワークフローの入力)と同じです。書かなければ、Enter を押すまで待ちます |

`schema` の `string` には、`multiline: true` も書けます。複数行の値です。ワークフローの入力には書けません。

標準入力と標準出力がどちらもターミナルなら、対話の形で聞きます。

- `choice` は、一覧から選びます。必須でなく `default` もなければ、答えないことも選べます
- `default` のある `boolean` は、y か n で確かめます
- `multiline` の値は、その場で複数行を入力します
  - Enter で確定します
  - Alt+Enter か、行の終わりの `\` のあとに Enter で、改行します
  - kitty keyboard protocol に対応したターミナルでは、Shift+Enter でも改行します
  - 貼り付けた文の改行は、そのまま残ります
- ほかの値は、1 行で入力します。宣言に合わなければ、理由を表示して、その場で直せます

パイプなどのときは、1 行ずつ読みます。`multiline` の値は、`.` だけの行で終わります。

答える前にターミナルの入力が終わると、ワークフローは失敗します。聞いているあいだの Ctrl+C は、ほかのときと同じです（「[ugoke run の Ctrl+C](commands/run.md#ctrlc)」）。

## ai ステップ

AI に指示を実行させるステップです。AI は、プロバイダーが動かします。使えるプロバイダーは、[リファレンス](README.md#ai-のプロバイダー)にあります。

| 項目              | 必須               | 内容                                                                                                                            |
| ----------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `type`            | はい               | `ai` です                                                                                                                       |
| `provider`        | はい               | AI を動かすプロバイダーの名前です。[プラグイン](plugins.md)が足します                                                           |
| `prompt`          | はい               | AI への指示です。[式](#式)を書けます                                                                                            |
| `model`           | いいえ             | 使うモデルです。プロバイダーにそのまま渡します。書かなければ、プロバイダーが選びます                                            |
| `schema`          | いいえ             | 結果の JSON Schema です。`type: object` で書きます。書かなければ、結果はテキストです                                            |
| `session`         | いいえ             | `reuse` か `new` です。既定は `reuse` です                                                                                      |
| `with`            | プロバイダーによる | プロバイダーのオプションです。文字列には[式](#式)を書けます                                                                     |
| `next`            | はい               | 次に実行するステップの ID か、`end` か、[分岐](#分岐)の一覧です                                                                 |
| `maxVisits`       | いいえ             | 1 つの実行で、このステップが動ける回数です。正の整数で書きます。書かなければ、上限はありません。[ループ](#ループ)を見てください |
| `timeout`         | いいえ             | ステップの最大の実行時間です。既定は `30m` です。書き方は script ステップと同じです                                             |
| `inputs`          | いいえ             | ステップが受け取る値です。名前と[式](#式)の組で書きます                                                                         |
| `outputs`         | いいえ             | ステップが出す値です。AI の結果を `result.data` で参照できます                                                                  |
| `env`             | いいえ             | このステップの環境変数です。名前と値の組で書きます。数と真偽値は、書いたとおりの文字列になります。値には[式](#式)を書けます     |
| `continueOnError` | いいえ             | `true` なら、ステップが失敗しても、ワークフローを続けます。[失敗しても続ける](#失敗しても続ける)を見てください                  |

- 作業ディレクトリは、プロジェクトのルートです
- 環境変数は、script ステップと同じです。ステップを実行するプロセスの環境変数を引き継ぎ、ワークフローの `env`、ステップの `env`、[`dotenv` のファイル](#dotenv-のファイル)を渡します。同じ名前の順も同じです
- AI が言ったことやしたことを、ステップの出力として表示します
- `schema` を書くと、結果は `schema` に合う値です。`outputs` では、`result.data.<名前>` のように中の項目も参照できます
- 同じ実行の中でステップがもう一度動くとき、`session` が `reuse` なら前のセッションを続け、`new` なら新しく始めます
- `timeout` を過ぎると、ステップは失敗します。失敗した ai ステップは、やり直しません。ファイルを変えたあとに失敗したかもしれないためです
- `schema` の `properties` に書いた項目が AI の結果になければ、その項目は `null` です。中のオブジェクトの `properties` も同じです
- 次の項目は、AI の結果になければ、`outputs` や分岐が参照したときに、ステップは失敗します。AI を動かしたあとです
  - `properties` に書いていない名前の項目。下の `schema` のときに参照できます
  - 配列の要素の中の項目
- 知らないプロバイダーと、プロバイダーの決まりに合わない `with` は、定義のエラーです。`with` の式を評価した値が決まりに合わないときは、AI を動かさずにステップが失敗します

`result.data` の中の項目は、`schema` の `properties` に書いた名前だけを参照できます。ただし、次の `schema` では、ほかの名前も参照できます。

- `additionalProperties` を `false` 以外で書いた
- `$ref`、`allOf`、`anyOf`、`oneOf`、`if`、`patternProperties`、`dependentSchemas`、`unevaluatedProperties` のどれかを書いた
- `properties` を書いていない

## 式

`${{ <参照> }}` の形で、ほかの値を参照します。参照は、`steps.fetch.outputs.title` のように `.` で区切った名前です。`${{ trim(steps.fetch.outputs.title) }}` のように、[ヘルパー関数](#ヘルパー関数)も呼べます。

`if` 以外の `${{ }}` の中に書けるのは、参照 1 つか、ヘルパー関数の呼び出し 1 つです。`'文字列'` などの値だけは書けません。`==` などの演算子と、値だけの式は、[分岐](#分岐)の `if` だけで使えます。

参照できる値と、それを使える場所は次のとおりです。

| 参照できる値                                                              | 使える場所                   |
| ------------------------------------------------------------------------- | ---------------------------- |
| 前に実行するステップの `outputs`（`steps.<ステップ>.outputs.<名前>`）     | `inputs`、`run`、`prompt`、`with`、ステップの `env`、`outputs`、分岐の `if`   |
| 前に実行するステップの、何回目かの `outputs`（`steps.<ステップ>.visits[<番号>].outputs.<名前>`） | 同じ |
| ワークフローの入力（`workflow.inputs.<名前>`）                            | `inputs`、`run`、`prompt`、`with`、ステップの `env`、`outputs`、分岐の `if`、ワークフローの `env`   |
| 自分の `inputs`（`inputs.<名前>`）                                        | `run`、`prompt`、`with`、ステップの `env`、`outputs`             |
| 自分の `outputs`（`outputs.<名前>`）                                      | 分岐の `if`                                    |
| 環境変数（`env.<名前>`）                                                  | 分岐の `if`                                    |
| スクリプトの結果（`result.exitCode`、`result.stdout`、`result.stderr`、`result.ok`、`result.error`） | script ステップの `outputs` と分岐の `if`      |
| 待機ステップの答え（`result.<名前>`）                                     | wait ステップの `outputs` と分岐の `if`        |
| AI の結果（`result.data`、`result.ok`、`result.error`）                   | ai ステップの `outputs` と分岐の `if`          |

- 前に実行するステップには、ループの後ろのステップも含みます
- まだ動いていないステップと、別の分岐で動かなかったステップの値は `null` です
- 宣言していない値は参照できません。参照した値の中の項目（`steps.fetch.outputs.title.text` など）も参照できません。`result.data` の中の項目は、[ai ステップ](#ai-ステップ)の `schema` で決まります
- 式だけで書いた値は、参照した値の型のままです。前後に空白と改行しかなければ、式だけとして扱い、空白と改行は取り除きます。たとえば、YAML の `|` で書いたときの最後の改行です。ほかの文字と続けて書いた値は、文字列になります。そのとき、`null` は空の文字列に、オブジェクトと配列は JSON になります
- `run`、`prompt`、`env` の値は、式だけで書いても、いつも文字列です。`null` とオブジェクトと配列は、ほかの文字と続けて書いたときと同じように文字列にします
- `null` を通る参照は、`null` です。たとえば、`result.data.a.b` で、`a` が `null` のときです
- ほかに読めない参照（配列の長さを超える番号など）があると、ステップは失敗します。`result.data` の中の項目は、[ai ステップ](#ai-ステップ)の決まりのとおりです
- `result.stdout` と `result.stderr` は、最後の改行を 1 つ取り除いた値です
- `result.ok` は、ステップが成功したかです。`result.error` は、失敗した理由です。成功したときは `null` です
- ステップが受け取る値（`inputs`、`run`、`prompt`、`env`、`outputs` が参照する値と、ワークフローの `env`、ai ステップの `with`）と出す値は、それぞれ JSON で 512 KiB までです。受け取る値が超えるとスクリプトや AI を動かさずに、出す値が超えると動かしたあとに、ステップは失敗します

`ugoke validate` と `ugoke run` は、実行する前に式を確かめます。

### ヘルパー関数

| ヘルパー関数     | 内容                                   |
| ---------------- | -------------------------------------- |
| `trim(<文字列>)` | 文字列の前後の空白と改行を取り除きます |

- 引数に書けるのは、参照、ヘルパー関数の呼び出し、`'文字列'`、数、`true`、`false`、`null` です。演算子は書けません
- ないヘルパー関数や、引数の数が違う呼び出しは、定義のエラーです
- 参照を含まない呼び出しは、実行する前に値を求めます。たとえば `trim(3)` は、定義のエラーです
- `trim` に文字列でない値を渡すと、ステップは失敗します。`null` も同じです。`null` になるのは、たとえば次の値です
  - 動かなかったステップの値
  - `default` がなく、渡されなかったワークフローの入力
  - 分岐の `if` で、設定されていない `env.<名前>`

## 分岐

`next` に `if` と `to` の一覧を書くと、ステップが成功したあとに、上から順に `if` の条件を確かめます。`continueOnError` のステップは、失敗したあとにも確かめます。最初に成り立った分岐の `to` に進みます。どれも成り立たなければ、最後の分岐の `to` に進みます。

```yaml
next:
  - if: ${{ outputs.verdict == 'approve' }}
    to: deploy
  - to: report
```

| 項目 | 必須 | 内容 |
| ---- | ---- | ---- |
| `if` | 最後の分岐では書かない。それ以外では必須 | 条件です |
| `to` | はい | 進むステップの ID か、`end` です |

条件は、`${{ }}` の式 1 つで書きます。

- 書けるのは、参照、[ヘルパー関数](#ヘルパー関数)の呼び出し、`'文字列'`、数（`1`、`-1`、`1.5`）、`true`、`false`、`null`、`==`、`!=`、`&&`、`||`、`!`、かっこです。文字列の中の `'` は、`''` と書きます
- 強く結び付く順に、`!`、`==` と `!=`、`&&`、`||` です。`==` と `!=` は、1 度に 2 つの値を比べます。`a == b == c` は書けません
- 値は、型を変えずに比べます。たとえば `1 == '1'` は成り立ちません
- 動かなかったステップの `outputs`、設定されていない `env.<名前>`、`null` を通る参照は、`null` です。ほかに読めない参照（配列の長さを超える番号など）があると、ステップは失敗します。`result.data` の中の項目は、[ai ステップ](#ai-ステップ)の決まりのとおりです
- オブジェクトと配列は、中身では比べません。中身が同じでも、別の値どうしは等しくありません
- `!`、`&&`、`||` に使う値と、条件の値は、`true` か `false` でなければなりません。そうでなければ、ステップは失敗します。ただし、`&&` と `||` は、左の値で決まるときは右の値を見ません
- 条件の値と、`!`、`&&`、`||` の値には、次の値を書けません。定義のエラーになります
  - `true` と `false` のほかの値。たとえば `'yes'`、`1`、`null`
  - `boolean` でないワークフローの入力
  - 必須でなく、`default` もない `boolean` のワークフローの入力。渡されないと `null` です
  - 前にいつも動くとは限らないステップの `outputs` と、2 回目からの `visits`（`visits[1]` から）。動いていなければ `null` です
- `null` になりうる値は、`== true` のように比べるか、`steps.b.outputs.ok != null && steps.b.outputs.ok` のように、前で `null` でないことを確かめます
  - 確かめたことになるのは、同じ参照を、`&&` の左で `!= null` と、`||` の左で `== null` と比べたときです
  - 右で比べたとき、項目を読んだとき（`a != null && a.b`）、`null` でない値と比べたとき（`a != false && a`）は、確かめたことになりません
- 自分の `outputs`、`result`、`env.<名前>`、ヘルパー関数の呼び出しは、実行のときに確かめます
- 参照できる値は、[式](#式)の表のとおりです。`env.<名前>` は、ステップが引き継いだ環境変数、`dotenv` のファイル、ワークフローの `env`、ステップの `env` を、ステップと同じ順で見ます。[`dotenv` のファイル](#dotenv-のファイル)は、`env` を参照する条件があるときだけ読みます

## 失敗しても続ける

`continueOnError: true` を書いた script ステップと ai ステップは、失敗しても、ワークフローを止めません。`next` に進みます。

```yaml
test:
  type: script
  run: npm test
  continueOnError: true
  outputs:
    passed: ${{ result.ok }}
  next:
    - if: ${{ result.ok }}
      to: deploy
    - to: report
```

- 失敗したステップの `result.ok` は `false` です。`result.error` は、失敗した理由です
- 結果の行には、`continued` が付きます（「[ugoke run の出力](commands/run.md#出力)」）
- `outputs` と分岐の条件は、失敗したあとも評価します
- 次のときは、`result.exitCode` は `null` で、`result.stdout` と `result.stderr` は空です。途中まで出した出力も入りません
  - スクリプトが `timeout` を過ぎた
  - スクリプトを動かせなかった。たとえば、`dotenv` のファイルが読めない
- 失敗した ai ステップの `result.data` は `null` です。その中の項目も `null` です
- 失敗した ai ステップは、セッションを残しません。同じステップがもう一度動くとき、`session: reuse` なら、その前に成功した回のセッションを続けます
- 出す値が 512 KiB を超えると、`outputs` はすべて `null` です
- 次のときは、`continueOnError` があっても、ワークフローは失敗します
  - 式を評価できない。たとえば、分岐の条件の値が `true` か `false` でない
  - 分岐の条件が `env` を参照していて、環境を読めない。たとえば、`dotenv` のファイルが読めない
  - 受け取る値が 512 KiB を超える
- 取り消したステップは、取り消しで終わります
- wait ステップには書けません

## ステップのつながり

ワークフローは `start` のステップから始まり、各ステップの `next` をたどって進みます。行き先が `end` のステップで終わります。ステップのつながりは、次のことを満たす必要があります。

- `start` と、`next` と分岐の `to` が指すステップが、定義にある
- どのステップも、`start` からたどって行ける
- どのステップからも、たどって `end` に着ける

いくつかのステップから、同じステップに進めます。前のステップや `start` のステップに戻って、ループを作ることもできます（「[ループ](#ループ)」）。

存在しないステップを指すステップは、`end` に着けないとは報告しません。`Unknown step` だけを報告します。

## ループ

前のステップに戻る `next` や分岐の `to` を書くと、ループになります。ループの中のステップは、何度でも動きます。`start` のステップに戻るときは、そのステップの ID を書きます。`start` は予約語のため、`next: start` とは書けません。

```yaml
steps:
  write:
    type: script
    run: ./write.sh
    maxVisits: 3
    next: check
  check:
    type: script
    run: ./check.sh
    outputs:
      verdict: ${{ result.stdout }}
    next:
      - if: ${{ outputs.verdict == 'retry' }}
        to: write
      - to: end
```

- `maxVisits` の回数だけ動いたステップにもう一度進むと、そのステップを動かさずに、ワークフローは失敗します
- 実行の記録が Temporal の上限に近づくと（40,000 のイベントか 40 MiB）、次のステップを動かさずに、ワークフローは失敗します。`maxVisits` のないループも、ここで止まります
- `steps.<ステップ>.outputs.<名前>` は、そのステップが最後に動いたときの `outputs` です。何回目かの `outputs` は、`steps.<ステップ>.visits[<番号>].outputs.<名前>` で参照します。番号は 0 から数えます。まだその回まで動いていなければ、値は `null` です
- ステップの中で自分の `steps.<ステップ>.…` を参照すると、前の回までの値です。今の回の値は、分岐の `if` から `outputs.<名前>` で参照します

## YAML の書き方の制限

次の書き方は、エラーになります。

- 定義にない項目
- 同じマップの中で重複したキー
- 1 つのファイルに複数のドキュメント（`---` で区切ったもの）
- YAML のアンカー（`&name`）とエイリアス（`*name`）
- `env` の値で、YAML が書いたのと違う値として読む数と真偽値。たとえば `1.10`（`1.1` と読む）、`00123`（`123` と読む）、`True`（`true` と読む）や、桁が多すぎて丸められる整数です。`"1.10"` のように引用符で囲みます
